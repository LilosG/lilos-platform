# OAuth and Secret Boundary

Production secret storage is an infrastructure adapter. The relational database stores opaque references and non-secret expiry/health metadata only. OAuth callback processing validates tenant-bound hashed state, expiry, exact redirect URI, one-time consumption, PKCE, and provider errors before storing returned credentials through that adapter. Callbacks are generic on failure and never echo codes or tokens.

`FernetSecretStore` (`apps/api/app/integrations/secrets.py`) is the approved initial `SecretStore` implementation: Fernet-encrypted ciphertext in the dedicated `provider_secrets` table, referenced only by opaque UUID. Every row is stamped with the `key_version` active at write time (`Settings.secret_encryption_key_version`, default `1`); reads require an exact version match. Rotation is not automated: this initial design holds exactly one active key at a time, so rotating requires (1) generating a new key/version, (2) extending the store to hold a keyring of `{version: key}` for decrypting retired rows during the transition, (3) an explicit re-encryption pass over every row below the new version, and (4) removing the retired key once no row references it. No keyring or re-encryption script exists yet.
